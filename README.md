## Выводы

В ходе выполнения задания я освоила основной цикл работы с Git и GitHub: от настройки окружения (SSH-ключ, конфигурация Git) до создания веток, Pull Request'ов, задач (issues) и автоматизации через GitHub Actions.

Основная трудность возникла на этапе настройки — команды не распознавались в обычной командной строке Windows, пока не открыла Git CMD. Также разобралась в разнице между `git fetch` и `git pull`, а также в том, зачем нужны ветки — чтобы не ломать основную рабочую версию проекта, пока изменения не проверены.

Ревью Pull Request планировалось получить от одногруппника, однако на момент выполнения задания привлечь второго участника не получилось — процесс мержа был протестирован самостоятельно с пониманием того, что в реальной командной работе этот шаг обязательно проходит через ревью другого человека.
